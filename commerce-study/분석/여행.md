# 여행상품 — 노랑풍선에 가까운 오픈소스

노랑풍선([ybtour.co.kr](https://www.ybtour.co.kr))의 패키지·자유여행은 커머스 variant가 아니다. 상품(`goodsCd`) 아래에 출발일이 여러 개 있고, 출발일마다 잔여석·최소출발·성인/아동/유아 가격이 있다. 가격에는 유류할증료·세금이 포함되고, 싱글차지가 따로 있다. 일정은 일차이고, 항공편·호텔·가이드·쇼핑 횟수가 그 상품에 붙어 있다. 호텔 이름은 출발 직전에 확정되기도 한다. 예약금은 인당이다. 항공만 고르는 화면(`fly.ybtour.co.kr`)은 이 출발일 목록과 다른 상품이다.

이 형태를 한 제품으로 공개한 성숙한 오픈소스는 없다. 아래는 조각이 공개된 것이다. 2026-10-11에 저장소·npm·플러그인 페이지를 확인했다.

---

## 상품 모델이 가까운 것

### Voyant 패키지 (Apache-2.0, npm)

[voyant.travel](https://voyant.travel/)는 여행사·투어 오퍼레이터·DMC용 예약 엔진이다. 도메인 모듈이 npm `@voyant-travel`에 Apache-2.0으로 올라가 있다. 패키지 메타데이터의 git 주소는 `github.com/voyant-travel/voyant`인데, 그 모노레포는 오늘 404다. 공개 git에 있는 것은 CLI, Connect SDK, 호텔 PMS, 결제 어댑터다.

| 패키지 | 하는 일 |
|--------|---------|
| `@voyant-travel/trips` | 여러 구성 예약을 고객 여정 하나로 묶는다. 일정, 가격, 홀드, 체크아웃 |
| `@voyant-travel/flights` | 항공 공급사 검색·예약. 카탈로그의 한 수직 |
| `@voyant-travel/accommodations` | 숙소 재판매 계약 |
| `@voyant-travel/cruises`, `charters` | 크루즈, 크루즈에 안 맞는 전세 |
| `@voyant-travel/bookings` | 예약 수명, 여행자, 공급사 상태 |
| `@voyant-travel/commerce` | 견적 시점의 시장, 가격, 프로모션, 판매 가능 여부 |
| `@voyant-travel/distribution` | 채널, 공급사, allotment, 채널 푸시 |
| `@voyant-travel/operations` | 가용, 자원 풀, 지상 물류 |
| `@voyant-travel/proposals` | 견적서와 버전 |

[`voyant-travel/pms`](https://github.com/voyant-travel/pms)는 그 프레임워크 위의 호텔 운영이다. 객실 타입, rate plan, 날짜별 요금·재고, 프론트, 하우스키핑. 노랑풍선의 패키지 출발일이 아니라, 호텔을 직접 운영하는 쪽이다. README는 프레임워크 모노레포를 전제로 한다.

버전은 0.x다. 노랑풍선 백오피스를 대체하는 완제품으로 보기보다, 상품을 “출발일 SKU”가 아니라 항공·숙소·크루즈를 묶는 여정으로 나눈 어휘로 본다.

### WP Travel Engine 코어 (GPLv3)

[wordpress.org/plugins/wp-travel-engine](https://wordpress.org/plugins/wp-travel-engine/). 설치 2만 이상. 트립, 일정, 성인·아동 같은 가격 범주, 1인 요금과 그룹 요금, 예약 최소 인원이 코어에 있다.

출발일과 그 날짜의 좌석 수는 **Trip Fixed Starting Dates** 유료 애드온이다. 날짜·패키지·시간대마다 좌석, 반복 출발, Available/Limited/Guaranteed, 카테고리별 좌석 상한을 둔다. 노랑풍선의 “잔여석 + 최소출발”에 가장 가까운 화면인데, 그 부분이 무료 코어 밖에 있다. 숙소 업그레이드도 유료 애드온이다.

같은 이름처럼 보이는 [WP Travel](https://wordpress.org/plugins/wp-travel/)은 다른 플러그인이다. Fixed Departure는 Pro 기능으로 안내된다.

### LSX Tour Operator (GPL-3.0)

[lightspeedwp/tour-operator](https://github.com/lightspeedwp/tour-operator). 투어, 목적지, 숙소 포스트 타입과 일차 일정, 지도. 콘텐츠 구조다. 잔여석이나 결제는 여기 없다. Wetu에서 일정을 가져오는 연동은 별도 플러그인이다.

## 호텔·날짜만 있는 것

노랑풍선 상품 안의 호텔 조각이지, 패키지 전체가 아니다.

| 프로젝트 | 라이선스 | 재고 |
|----------|----------|------|
| QloApps | OSL-3.0. 이 폴더에 분석이 있다 | 객실 타입 × 날짜. `stock_available`은 더미 |
| HotelDruid | AGPL-3.0. [hoteldruid.com](https://www.hoteldruid.com/). GitHub 미러 `digital-druid/hoteldruid`는 2018년에서 멈춤 | 방·아파트의 숙박 |
| Drupal BAT | [drupal.org/project/bat](https://www.drupal.org/project/bat) | 예약 가용성 프레임워크. 객실 달력 |

## 소스는 보이나 오픈소스가 아닌 것

| 이름 | 상태 |
|------|------|
| [iTourTMS](https://github.com/mg-gouda/iTourTMS) | GitHub에 코드가 있다. README는 독점 라이선스이고, 설치 때 1년짜리 라이선스 키가 없으면 동작이 멈춘다고 적는다. 모듈은 호텔 계약(시즌 요금, allotment, stop sale), 예약, 교통, B2B 포탈 |
| PHPTRAVELS | 소스를 포함하는 유료 라이선스. 고정 출발·견적·DMC 원가를 판다 |
| Rezdy, Bokun, Xola, Checkfront, FareHarbor, TourCMS | 투어 오퍼레이터 상용 플랫폼. 공개 상품 모델이 없다 |

항공 요금 조회(노랑풍선 `fly`)에 해당하는 오픈소스 GDS는 없다. Amadeus·Sabre·Galileo와 국내 발권 시스템은 이 목록의 “일부러 빼는 것”에 이미 있는 Amadeus와 같은 자리다.

## 이 스터디의 재고와 어떻게 다른가

| 노랑풍선 | 가까운 기존 노트 |
|----------|------------------|
| 상품 1개, 출발일 N개, 출발일마다 잔여석 | pretix 서브이벤트, alf.io 이벤트. 둘 다 행사 하나다. 상품이 출발일 목록을 거느리는 구조는 아니다 |
| 성인·아동·유아가 같은 잔여석을 나눠 씀 | WP Travel Engine이 설명하는 공유 좌석 풀. [통합재고.md](통합재고.md)의 “여러 판매 단위가 한 수량”과 같다 |
| 최소출발 인원 | 좌석 상한과 다른 제약. 팔린 수가 이 값 미만이면 출발 미확정 |
| 싱글차지 | 가격 가산. 좌석을 새로 만들지 않는다 |
| 일정·항공·호텔 문구 | LSX의 일차 콘텐츠. 재고 키가 아니다 |
| 호텔만 파는 경우 | QloApps의 방 × 날짜 |
