# 핵심 단어

같은 영어가 프로젝트마다 다른 층을 가리킨다. 이 문서의 한국어는 그 층을 부를 때의 뜻이다. 프로젝트 원문은 각 분석 파일에 있다. Talket 대응은 [talket/비교.md](talket/비교.md)다. Talket 자체는 [talket/README.md](talket/README.md)다.

## 이 노트에서 고정하는 뜻

| 한국어 | English | 층 |
|--------|---------|----|
| 상품 | product | 이름·설명·정책의 그릇. 그 자체가 판매 단위인 곳도 있다 |
| 판매 단위 | sellable, variant, SKU | 장바구니에 담기는 것. 가격과 재고가 붙는 자리 |
| 옵션 축 | option, option type | 색·사이즈처럼 판매 단위를 가르는 축 |
| 개별 단위 | unit, position, ticket | 수량 1개짜리 권리 또는 재고 행 |
| 선반 | on-hand, stocked | 물리 수량 |
| 가용 | available | 지금 팔 수 있는 수 |
| 홀드 | hold, reservation | 결제 전 소프트 점유 |
| 할당 | allocation, committed | 주문에 묶인 하드 점유 |
| 쿼터 | quota | 용량 숫자. 사용량은 주문·카트를 합산 |
| 정원 | capacity | 그 칸의 최대 수 |
| 주문 줄 | line | 판매 단위 + 수량 + 단가 스냅샷 |
| 환불 | refund | 돈의 반환 |
| 반품 | return | 물건의 반환 |
| 이행 | fulfillment | 배송, 체크인, 사용, 객실 배정 |

## 1. 상품

### Product — 상품

그릇인 곳과, 그 자체가 판매 단위인 곳이 있다.

| 프로젝트 | 로컬 이름 | 가리키는 것 |
|----------|-----------|-------------|
| Talket | `Product` (`NftCollection`, `t_product`) | 그릇. 카테고리, 판매 기간, 배송·환불 정책. 가격·정원은 옵션 |
| Medusa, Saleor, Spree, Shopify | `Product` | 그릇. 담는 것은 Variant |
| commercetools | Product | 그릇. 문서가 “그 자체는 못 판다”고 못 박음 |
| pretix | `Item` | 판매에 가까운 그릇. 변형이 없으면 아이템이 판매 단위 |
| alf.io | `Event` + `TicketCategory` | 행사가 그릇, 권종이 판매 단위 |
| QloApps | `Product` (`booking_product = 1`) | 객실 타입. 물리 방은 다른 테이블 |
| Easy!Appointments | `services` | 판매 단위이자 시간 길이. 상품 그릇 없음 |
| LibreBooking | `BookableResource` | 예약 대상. 상품 계층 없음 |
| Magento | `catalog_product_entity` | 행은 하나. `type_id`가 그릇인지 판매 단위인지 가름 |
| Akeneo | Product model / Product | 모델은 공통 값(SKU 없음). Product가 내보내는 판매 단위 |
| Stripe | Product | 이름·이미지. 청구 단위는 Price |
| Odoo | `product.template` | 그릇. 판매·재고는 `product.product` |

### Item — 품목 / 아이템

세 층을 한 단어로 부른다.

| 뜻 | 프로젝트 | 로컬 이름 |
|----|----------|-----------|
| 판매 상품 | pretix | `Item`. `admission`이면 입장권 |
| 재고 SKU | Medusa, Shopify | `InventoryItem`. Variant와 링크. 키트면 여러 개 |
| 발행된 권리 1개 | Talket | `ProductItem` (`Nft`, `t_product_item`). 결제 후에 행이 생김 |
| 주문 수량 1개 | Talket | `OrderItem` (`TradeSaleUnit`). id가 곧 나중 아이템 id |
| 주문 줄의 스냅샷 | Medusa | `order_line_item` |
| 출고 조각 | Spree 6 | `FulfillmentItem` (예전 `InventoryUnit`) |

### Variant — 변형

판매 단위의 이름이다. Talket은 이 단어를 쓰지 않고 `ProductOption`을 쓴다.

| 프로젝트 | 로컬 이름 | 만드는 법 |
|----------|-----------|-----------|
| Medusa, Saleor, Spree, Shopify, commercetools | `ProductVariant` / `Variant` | 옵션 축 값의 조합. 체크아웃 라인은 여기만 가리킴 |
| Odoo | `product.product` | 색×사이즈면 조합 개수만큼 행 |
| Magento configurable | 자식 `simple` | 카탈로그에서도 독립 상품. `catalog_product_super_link` |
| Akeneo | Product (부모 있음) | family variant의 마지막 단. 축은 최대 2단 |
| pretix | `ItemVariation` | 사이즈·등급. 정원은 변형이 아니라 `Quota` |
| Talket | `ProductOption` | 조합이 아니다. “VIP”, “S”처럼 이름 칸을 직접 만듦 |

### Option — 옵션

축인 곳과, 판매 칸인 곳이 있다.

| 뜻 | 프로젝트 | 로컬 이름 |
|----|----------|-----------|
| 판매 칸 (가격·정원) | Talket | `ProductOption` (`NftPublicSale`) |
| 변형 축 (Color, Size) | Medusa `ProductOption`, Saleor 속성, Spree `OptionValue`, Shopify 옵션 정의 | 값의 조합이 Variant가 됨 |
| SKU가 안 갈라지는 각인 | Magento custom option, pretix `Question`, alf.io 필드, QloApps textfield, Talket `SHORT_TEXT` | 구매자가 타이핑. 자세한 표는 [직접입력-옵션.md](직접입력-옵션.md) |
| 추가 구매 | pretix `ItemAddOn` | 본품이 고르는 카테고리. 줄이 따로 생김 |
| 소유 후 혜택 | Talket `ProductUsage` | 티켓·바우처·수령. `ONCE` / `DAILY`. 재고를 안 깎음 |

### SKU

재고와 가격이 붙는 코드다.

| 프로젝트 | SKU가 사는 곳 |
|----------|----------------|
| Medusa, Saleor, Spree, Shopify, commercetools, Odoo | Variant |
| Magento simple / virtual | 그 상품 행 |
| pretix | 아이템 또는 변형. 쿼터는 별도 |
| Talket | 옵션 id. 별도 SKU 문자열은 판매의 기준이 아님 |
| Stripe | Product id를 SKU로 쓸 수 있음. 재고 수량은 없음 |
| Easy!Appointments, LibreBooking | SKU 없음 |

### Bundle — 번들

| 프로젝트 | 의미 |
|----------|------|
| pretix `ItemBundle` | 본품을 사면 `count`만큼 구성품 줄이 붙음. `require_bundling`이면 혼자 안 팔림 |
| Magento `bundle` | 고객이 고르는 구성. 자식 simple이 재고를 가짐 |
| Shopify | 구성품 번들. selling plan과 같이 못 팜 |
| Medusa | Variant 1개가 `InventoryItem` 여러 개. `required_quantity` |
| Talket `CreateProductBundle` | 상품·옵션·사용·콘텐츠를 한 요청으로 만드는 명령. 구성품 재고 없음 |
| Talket `ProductGroup` | 진열 묶음. Magento `grouped`에 가깝고 재고는 멤버 각자 |

### Channel — 채널

| 프로젝트 | 의미 |
|----------|------|
| Saleor `Channel` | 통화, 공개, 가격, 창고 배분, 결제 정책 |
| commercetools Price / `supplyChannel` | 가격의 판매 채널, 또는 재고의 창고·매장 |
| Shopify `Location` | 재고 장소. 판매 채널과 이름이 다름 |
| Talket | 채널 없음. 가격·공개는 상품·옵션에 붙음 |

## 2. 재고

### Stock / Inventory — 재고

| 프로젝트 | 말이 가리키는 것 |
|----------|------------------|
| Medusa | `inventory_level.stocked_quantity`. 장소별 선반 |
| Saleor | `warehouse_stock.quantity`. 창고 × variant |
| Spree 6 | `stock_level.count_on_hand`. 변화는 `StockMovement` |
| Shopify | 장소마다 `available`, `committed`, `on_hand`, `incoming` 버킷 |
| Odoo | `stock.quant`. 장소·로트·패키지·소유자. `stock.move`는 장소 → 장소 |
| Sharetribe | `listing.currentStock`. 증감은 불변 adjustment |
| Magento MSI | `inventory_source_item`이 창고 수량. 판매 가능 수는 그 합에 reservation을 더해 계산 |
| QloApps | `stock_available`은 999999999 같은 더미. 진실은 방 × 날짜 |
| pretix, Talket | 선반 컬럼이 기준이 아님. 용량에서 주문을 뺌 |
| Easy!Appointments, LibreBooking | 정수 선반 없음. 시간 겹침. LibreBooking 악세서리만 수량 |

### Available / On-hand — 가용 / 선반

```
커머스 세 곳: 가용 = 선반 − 할당 − (있으면) 체크아웃 홀드
Talket:       가용 = totalCount − VERIFIED·PAID·부분취소 수량
pretix:       가용 = quota.size − 주문 − 미만료 카트 − 바우처
```

| 말 | 선반을 언제 깎나 |
|----|------------------|
| Medusa `stocked_quantity` | 출고 |
| Saleor `quantity` | 출고 |
| Spree `count_on_hand` | `shipped` 이동 |
| Shopify `on_hand` | 받기·재고 조정. 주문은 `committed`만 올림 |
| Talket `totalCount` | 출고해도 안 깎임. 취소는 합에서 빠져 가용이 늘어남 |
| FastBooking `reserved` | 예약 때 증가, 취소 때 감소. 선반과 할당이 한 칸 |

Shopify `available`은 “주문에 안 묶인 수량”이다. Talket의 남은 정원과 같은 역할이고, 선반 숫자는 아니다.

### Reservation — 예약

다섯 가지를 이 단어로 부른다.

| 뜻 | 프로젝트 | 로컬 이름 |
|----|----------|-----------|
| 체크아웃 홀드 (TTL) | Saleor | `warehouse_reservation`. 체크아웃 라인 |
| 주문에 묶인 수량 | Medusa | `reservation_item` + `reserved_quantity`. 주문 확정 때 생성. 카트는 검사만 |
| 판매 가능 수량 로그 | Magento MSI | reservation. 소스 수량과 더해 salable quantity |
| 거래가 잡아 둔 정수 | Sharetribe | stock reservation. 거래당 하나. `pending`은 즉시 음수 adjustment |
| 예약 그 자체 (주문 자리) | LibreBooking, Easy!Appointments, QloApps, VoxelBooking | `Reservation`, `appointments`, `htl_booking_detail`, `bookings` |
| 카트 만료 | pretix | `CartPosition.expires`. 테이블 이름은 reservation이 아님 |
| 아이템 id 선점 | Talket | Redis ID 풀. 재고 예약 테이블 없음. `VERIFIED` 줄이 할당 역할 |

Sharetribe `proposed`는 수량을 검사만 한다. Talket `SUBMITTED` / `PENDING`과 같다. 둘 다 가용 합에 안 들어간다.

### Allocation / Committed — 할당 / 약속

| 프로젝트 | 로컬 이름 | 생기는 때 |
|----------|-----------|-----------|
| Saleor | `warehouse_allocation`, `quantity_allocated` | 주문 생성 |
| Spree 6 | `allocated_count`, movement `allocated` | 주문 완료. 선반은 출고 때 |
| Shopify | `committed` | 주문·드래프트. 앱이 직접 못 바꿈 |
| FastBooking | `BookingAllocation` | 테이블·시설을 줄에 붙임. 호텔·티켓은 `reserved` 카운터 |
| alf.io | 티켓 행을 예약에 연결 | `PENDING`. unbounded는 이 순간 `category_id`를 붙임 |
| Talket | 주문 줄 상태 | `VERIFIED`부터 합에 포함. 할당 테이블 없음 |

### Quota / Capacity — 쿼터 / 정원

| 프로젝트 | 말이 가리키는 것 |
|----------|------------------|
| pretix `Quota` | 아이템·변형·회차가 공유할 수 있는 용량 풀. `size`만 저장. 표는 [통합재고.md](통합재고.md) |
| Talket `totalCount` | 옵션 하나의 정원. 다른 옵션과 풀을 안 나눔 |
| VoxelBooking capacity | 그 시각의 `party_size` 합이 `max_capacity` 이하 |
| Easy!Appointments `attendants_number` | 그 슬롯·그 서비스의 동시 인원 |
| LibreBooking | 자원의 `MaxConcurrentReservations`. 악세서리는 `accessory_quantity` |
| FastBooking events | `TicketType.capacity`. `reserved + quantity`와 비교 |
| QloApps | 물리 방의 개수 × 날짜. 타입의 재고 숫자는 더미 |
| commercetools | 쿼터 단어 없음. `InventoryMode`가 라인마다 선점 시점만 고름 |

## 3. 주문

### Cart / Checkout / Order — 장바구니 / 체크아웃 / 주문

| 프로젝트 | 담기 | 확정 문서 |
|----------|------|-----------|
| Medusa | Cart. 재고는 검사 | `completeCart`가 Order |
| Saleor | Checkout + Reservation | Order + Allocation |
| Spree 6 | `Cart` 테이블 | `Order` 테이블. 완료 때 넘어감 |
| pretix | `CartPosition` (만료 있음) | `Order` + `OrderPosition` |
| alf.io | 티켓을 `PENDING`으로 집음 | `TicketReservation`이 주문 헤더 |
| Talket | `t_cart`는 수량 목록. 재고 홀드 없음 | `Order` (`NftTrade`, `t_order`). 제출 때 생성, 결제 후 `PAID` |
| QloApps | `htl_cart_booking_data`는 그 손님만의 장부 | PrestaShop `Order` + `htl_booking_detail` |
| Sharetribe | 거래(transaction)의 `proposed` | `accepted` |
| Easy!Appointments, LibreBooking | 주문 문서 없음 | 예약 행이 곧 확정 |
| Stripe | Checkout Session | 라인은 Price id |

Talket 클래스 이름 `NftTrade`는 주문이다. alf.io `TicketReservation`도 주문 헤더다. LibreBooking `Reservation`은 시간 점유 문서라 결제가 없다.

### Line / Position / Unit — 줄 / 포지션 / 단위

| 프로젝트 | 수량 N의 줄 | 수량 1의 조각 |
|----------|-------------|---------------|
| Medusa, Saleor, Spree | Order line / line item. 수량 컬럼 | 출고 아이템이 따로 있을 수 있음 |
| pretix | `AbstractPosition`. 카트와 주문이 같은 모양. 보통 1장 | 포지션 자체가 티켓. QR `secret` |
| Talket | `OrderLine` (`NftTradeSale`). `initialQuantity`, `currentQuantity` | `OrderItem`. 개수 = `nftIds` 길이 |
| FastBooking | `Booking` | `BookingAllocation` (자리·테이블·시설) |
| QloApps | 상품 카트 수량 = 방 수 × 박 수 | `htl_booking_detail` 한 행이 방 1개 × 기간 |
| commercetools | 라인. 창고가 둘이면 라인을 둘로 나눔 | 한 라인에 창고를 여러 개 안 싣음 |

pretix 포지션과 Talket `OrderItem`은 “1장”이라는 점이 같다. pretix는 담을 때 포지션이 생기고, Talket은 주문 제출 때 id만 정해지고 상품 아이템 행은 결제 후다.

## 4. 돈과 사후

### Price — 가격

| 프로젝트 | 금액이 붙는 곳 |
|----------|----------------|
| Talket | 옵션 `nominalPrice`(명목), `price`(판매). 통화 KRW. 주문 아이템에 단가 복사 |
| Medusa | `Price` → PriceSet → Variant 링크 |
| Saleor | `ProductVariantChannelListing` |
| Spree | `Price`. 통화, price list, 수량 구간 |
| pretix | 아이템·변형 |
| Stripe | `Price`. Product는 이름. 금액을 고치면 새 Price를 만들고 옛 것은 `active=false` |
| QloApps | 기본가 + 기간·요일 feature pricing |
| Easy!Appointments | `services.price`는 화면 숫자. 결제 없음 |

### Refund / Return / Claim / Cancel — 환불 / 반품 / 클레임 / 취소

| 말 | 고정 뜻 | 프로젝트에서의 범위 |
|----|---------|-------------------|
| Refund | 돈 | Medusa `Refund`(캡처 한도). Saleor `OrderGrantedRefund`. pretix `OrderRefund`. Talket `OrderRefund`(현금·포인트·배송비). Stripe Refund |
| Return | 물건이 돌아옴 | Medusa `Return`(수령 시 선반 증가). Spree 6 `Return` 하나(`requested → refunded`). QloApps `order_return` |
| Claim | 사후 절차 | Talket `Claim`: `CANCEL`, `CANCEL_REQUEST`, `RETURN`. Medusa `OrderClaim`은 반품·교환과 별도 문서 |
| Exchange | 교환 | Medusa `OrderExchange` (`difference_due`). Talket 교환 타입 없음 |
| Cancel | 점유를 뺌 | pretix 주문 `canceled`면 다음 쿼터 합에서 제외. Talket 줄 `PAID_CANCELED`. Voxel `status = cancelled`. Easy는 행 DELETE |
| Release | 재고 행을 풀로 | alf.io 티켓 `RELEASED`. unbounded는 `category_id`를 null로. Talket은 행을 풀에 안 넣고 소유 잔액만 회수 (`CLAIM_RETRIEVED`) |
| Restock | 선반 증가 | Shopify 환불의 restock 타입. Medusa·Saleor·Spree의 반품 입고. Talket·pretix는 선반을 안 올리고 합에서 빠짐 |
| Fee | 줄 밖의 금액 | pretix `OrderFee` 취소 수수료. QloApps 환불 규칙(기간 밖이면 0). Talket은 수수료 행 없음. `NO_REFUND`와 클레임 마감 |

## 5. 이행

### Fulfillment / Delivery / Check-in — 이행 / 배송 / 체크인

| 프로젝트 | 확정 다음의 일 | 로컬 이름 |
|----------|----------------|-----------|
| Medusa, Saleor | 출고 때 선반 감소 | fulfillment. Saleor는 할당 해제 + `quantity` 감소 |
| Spree 6 | 출고 | `Fulfillment`, `FulfillmentItem` `shipped` |
| Talket 굿즈 | 송장 | `Delivery`: `OUT_FOR_DELIVERY` → `DELIVERED`. 정원은 그대로 |
| Talket 티켓 | 사용 | `ProductUsage` `ONCE` / `DAILY`. 사용 이력 |
| pretix | 입장 | `Checkin` 행을 포지션에 쌓음 |
| alf.io | 입장 | 티켓 `CHECKED_IN` |
| QloApps | 숙박 | `ASSIGNED → CHECKED_IN → CHECKED_OUT` |
| LibreBooking | 자원 사용 | `enable_check_in`, 미체크인 자동 해제 |
| Odoo | 장소 이동 | `stock.picking`이 move를 묶음 |

Talket `confirmPeriod` / `confirmFixedTime`은 구매 확정 시각이다. 체크인 시각이 아니다. 더 이른 쪽을 주문 아이템에 복사한다.
