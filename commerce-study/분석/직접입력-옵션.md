# 직접 입력 옵션 — 등번호처럼 구매자가 텍스트를 넣는 칸

유니폼 등번호처럼 **구매자가 값을 타이핑하고, 그 값이 새 SKU를 만들지 않는** 입력만 모았다. 색·사이즈처럼 미리 만들어 둔 값을 고르는 옵션은 여기 없다.

판매자가 카탈로그에 적어 두는 설명 텍스트(Saleor `plain-text`)와, 구매 화면에서 받는 텍스트는 다른 층이다.

---

## 있는 곳

| 프로젝트 | 입력 | 붙는 자리 | 재고 |
|----------|------|-----------|------|
| Magento | `field` 한 줄, `area` 여러 줄 | 상품 custom option. 견적 줄의 option value | 부모 simple의 재고. 옵션별 SKU 없음. 가격 가산은 가능 |
| QloApps | `CUSTOMIZE_TEXTFIELD` (`1`) | PrestaShop customization. `customized_data.value` | 객실 재고와 별개. 파일은 `CUSTOMIZE_FILE` (`0`) |
| pretix | `TYPE_STRING` 한 줄, `TYPE_TEXT` 여러 줄 | 답이 `OrderPosition` / `CartPosition`. 기본은 티켓 1장. 특정 `Item`에만 연결 | 쿼터를 나누지 않음. 최소·최대 글자 수 |
| alf.io | `input:` 한 줄, `textarea` | 참석자 `ATTENDEE` 또는 부가상품. 권종 `categoryIds`로 제한 | 티켓 행을 더 만들지 않음. `minLength` / `maxLength` |
| LibreBooking | `SINGLE_LINE_TEXTBOX` `1`, `MULTI_LINE_TEXTBOX` `2` | 예약 `RESERVATION`의 custom attribute | 자원 시간 재고와 무관 |
| Talket | `SHORT_TEXT`, `LONG_TEXT` | 구매자 정보 폼. 제출은 주문 줄 | `ProductOption`의 가격·정원과 별개 |

### Magento

custom option 그룹은 `text`, `file`, `select`, `date`다. 등번호에 해당하는 타입은 텍스트 그룹의 `field`(한 줄)와 `area`(여러 줄)다.

값은 견적 줄 옵션에 문자열로 남는다. 변형(simple SKU)을 만들지 않는다. 선택형(`drop_down`, `radio`, `checkbox`)과 한 상품에 같이 둘 수 있다.

`magento2/app/code/Magento/Catalog/Api/Data/ProductCustomOptionInterface.php`

### QloApps

PrestaShop 상품 맞춤 입력을 그대로 갖고 있다. 호텔 예약 재고와는 다른 기능이다.

| 상수 | 값 | 의미 |
|------|----|------|
| `CUSTOMIZE_FILE` | 0 | 파일 |
| `CUSTOMIZE_TEXTFIELD` | 1 | 텍스트 |

필드 이름·필수 여부는 `customization_field`다. 구매자가 넣은 문자열은 `customized_data.value`다.

`QloApps/classes/CustomizationField.php`  
`QloApps/classes/Product.php` (`_CUSTOMIZE_TEXTFIELD_`)  
`QloApps/classes/Customization.php`

### pretix

`Question`이 티켓에 붙는 입력 칸이다. 문서의 예는 “참석자 나이”다. 등번호는 `TYPE_STRING`이다.

답은 `QuestionAnswer`로 `OrderPosition` 또는 `CartPosition`에 붙는다. `container_type` 기본값은 포지션(`P`)이라 티켓 1장마다 따로 받는다. 주문 헤더(`O`)에 한 번만 물을 수도 있다. `items`로 특정 상품에만 연결한다.

한 줄·여러 줄 외에 숫자, 예/아니오, 목록, 파일, 날짜, 전화가 있다. 문자열은 최소·최대 길이가 있다. 체크인 때 묻거나, 그때 답을 보여 줄 수 있다.

`pretix/src/pretix/base/models/items.py` (`class Question`)

### alf.io

`PurchaseContextFieldConfiguration.field_type`이다.

| type | 의미 |
|------|------|
| `input:`로 시작 | 한 줄. `input:dateOfBirth`처럼 콜론 뒤가 세부 타입. 없으면 text |
| `textarea` | 여러 줄 |
| `select`, `checkbox`, `country`, `vat:eu` | 고르는 값. 자유 텍스트가 아님 |

`context`는 `ATTENDEE`(티켓), `ADDITIONAL_SERVICE`, `SUBSCRIPTION`이다. `categoryIds`가 있으면 그 권종만 해당한다. `minLength` / `maxLength`, 필수, 체크인 화면 표시가 있다.

`alf.io/src/main/java/alfio/model/PurchaseContextFieldConfiguration.java`

### LibreBooking

예약 추가 질문이다. 상품 옵션 축이 아니다.

| 타입 | 값 |
|------|----|
| `SINGLE_LINE_TEXTBOX` | 1 |
| `MULTI_LINE_TEXTBOX` | 2 |
| `SELECT_LIST` | 3 |
| `CHECKBOX` | 4 |
| `DATETIME` | 5 |

카테고리 `RESERVATION`(1)이면 예약 한 건에 붙는다. `USER`, `RESOURCE`도 있다.

`librebooking/Domain/CustomAttribute.php`

### Talket

구매자 정보 폼 필드다. 판매 옵션(`ProductOption`)이 아니다. 가격과 정원을 나누지 않는다.

| 타입 | 의미 |
|------|------|
| `SHORT_TEXT` | 한 줄 |
| `LONG_TEXT` | 여러 줄 |
| `RADIO`, `CHECKBOX` | 고르는 값 |
| `FILE_UPLOAD` | 파일 |
| `STUDENT_ID` 등 | 정해진 형식의 식별자 |

제출은 주문 줄(`orderLineId`)에 연결된다. 줄 하나에 제출을 여러 개 둘 수 있다. 수량 1장마다 강제되는 포지션 모델은 pretix·alf.io 쪽이다.

`packages/contract/src/form/models/FormFieldType.ts`  
`packages/form/src/domain/models/OrderBuyerInfoFormSubmissionContext.ts`

## 이름이 비슷하지만 등번호 입력이 아닌 것

| 프로젝트 | 있는 것 | 구매자가 타이핑하는 칸이 아닌 이유 |
|----------|---------|-----------------------------------|
| Saleor | 속성 `plain-text`, `rich-text` | 판매자가 상품에 적는 값. 변형 축(`ALLOWED_IN_VARIANT_SELECTION`)에도 없음 |
| Odoo | `create_variant = no_variant` | 라디오·셀렉트 등 미리 만든 값. 자유 텍스트 타입 없음 |
| Easy!Appointments | `users.custom_field_1`–`5` | 고객 프로필 컬럼. 예약 한 건의 옵션이 아님 |
| Medusa, Spree | `ProductOption` / `OptionType` | 값 목록. 조합이 Variant |
| Akeneo | 텍스트 속성 | PIM에서 편집자가 채움 |
| Stripe | Product 설명 | 카탈로그 문구. 주문 줄 입력 없음 |

Shopware Custom Products는 [추가-학습.md](추가-학습.md)에 “SKU를 만들지 않는 각인 텍스트·파일”로만 있다. 이 워크스페이스에는 소스가 없다.

## 줄에 남기는 방식

| | 1개당 | 저장 |
|--|-------|------|
| pretix, alf.io | 티켓(포지션) 1장 | 질문 답 행 |
| Magento, QloApps | 장바구니 줄의 맞춤 입력 | option value / `customized_data` |
| LibreBooking | 예약 1건 | custom attribute 값 |
| Talket | 주문 줄당 폼 하나. 같은 `formId`를 줄에 두 번 내면 거절 | 폼 답. `orderItem` id는 없음 |

어느 쪽이든 입력값은 판매 단위의 신원이 아니다. 같은 “유니폼 M” SKU 아래 등번호만 달라진다.

## 재고를 보는가

텍스트 값 자체는 재고 키가 아니다. 검사하는 수량은 항상 부모 판매 단위다.

| 프로젝트 | 재고가 세는 것 | 텍스트가 그 검사에 들어가는가 |
|----------|----------------|------------------------------|
| Magento | simple(또는 그 MSI 소스)의 판매 가능 수량 × 줄 수량 | 아니오. `field`/`area`에 수량 컬럼이 없다. 금액 가산만 있다 |
| QloApps | 방 × 날짜 겹침 | 아니오. `customized_data`는 가용 조회에 없다 |
| pretix | 쿼터 합산 (주문·카트·바우처) | 아니오. `QuestionAnswer`는 `QuotaAvailability` 밖에 있다 |
| alf.io | `FREE` 티켓 행을 집는 수 | 아니오. 필드는 이미 집힌 티켓에 붙는다 |
| LibreBooking | 자원 시간 겹침 | 아니오. 속성 검증은 충돌 검사와 다른 규칙이다 |
| Talket | `totalCount` − `VERIFIED`·`PAID`·부분취소 줄 수량 | 아니오. `NftTradeStockValidator`는 옵션 id와 수량만 본다 |

그래서 “7번 등번호는 한 장만”은 이 입력으로는 안 된다. 그 제약은 값을 재고 키로 삼을 때 생긴다. 유한한 번호 목록을 판매 칸(또는 pretix 쿼터, alf.io 티켓 행)으로 두는 설계다. 자유 텍스트는 중복을 막지 않는다.

Magento·QloApps·Talket은 줄 수량 전체에 문자열 하나가 걸린다. 3장을 한 줄로 사면 등번호도 하나다. pretix·alf.io는 티켓 1장마다 답을 받는다. 재고 횟수는 그래도 티켓 수이지, 문자열 종류 수가 아니다.

## 톡켓 구매폼으로 대체할 수 있는가

구매폼은 이미 “SKU를 만들지 않는 텍스트”다. 상품 또는 옵션에 `FormContext`로 붙이고, 필수면 주문 저장 때 빠지면 거절한다. 재고 락과 무관하다.

맞는 경우:

- 줄에 답이 하나면 된다. 수령인, 단체명, 대표 연락처.
- 가격이 텍스트에 따라 변하지 않는다.
- 발행된 `ProductItem`마다 다른 문구를 찍지 않는다.
- 같은 번호의 중복 판매를 막지 않는다.

코드가 그 범위를 고정한다. `SubmitOrderBuyerInfoProcessor`는 한 주문 줄에서 같은 `formId`를 두 번 받으면 거절한다. 컨텍스트 키는 `orderLineId`이고 `OrderItem` id가 없다. 수량 3의 줄은 등번호 칸이 하나다.

어긋나는 경우:

- 장마다 다른 등번호. pretix 포지션, alf.io `ATTENDEE`의 단위다. Talket에서는 `OrderItem` 1개 = `ProductItem` 1개인데, 폼은 그 행에 안 붙는다.
- 입력마다 추가 금액. Magento custom option의 `price`다. 폼 답은 `PriceCalculator`에 없다.
- 번호 재고. 폼 답을 옵션 락 안의 합산에 넣지 않는다.

폼을 수량만큼 복제하는 방식으로 장당 입력을 만들 수는 있다. 지금 저장 키는 줄당 폼 하나라, 그 복제는 폼 모델을 바꾸는 일과 같다.

## 판매 옵션으로 만드는 편이 나은가

`ProductOption`을 등번호마다 만들면 그 번호가 정원이 된다. “7번은 1장”이 되고, 결제 확정 합산이 그대로 적용된다. 대가는 번호 하나가 판매 칸 하나라는 점이다. 가격·한도·ID 풀·진열이 번호마다 갈라지고, 자유 입력은 사라진다.

자유 텍스트를 `ProductOption`의 새 종류로 넣으면 재고 모델이 둘로 갈라진다. 지금 옵션은 “이름 칸 = 정원”이다. 텍스트 칸은 정원이 없다. 한 테이블에 넣으면 `totalCount`의 의미가 칸마다 달라진다.

남길 자리는 판매 칸과 폼 사이다. pretix `Question`, alf.io 필드와 같다.

- 정의는 상품 또는 옵션에 둔다. 라벨, 필수, 최소·최대 길이.
- 답은 `OrderItem`에 둔다. 장마다 하나. 발행된 아이템이 그 문자열을 가져간다.
- 재고 키에는 넣지 않는다. 부모 옵션 `totalCount`만 센다.
- 줄에 한 번이면 되는 질문(수령인, 학번)은 지금 구매폼을 유지한다.

정리하면, 재고가 필요 없는 줄 단위 문구는 구매폼이 맞다. 장마다 다른 문구는 구매폼의 반복이 아니라 `OrderItem`에 붙는 입력이다. 번호 개수를 재고로 팔 때만 그 번호를 `ProductOption`으로 만든다.
